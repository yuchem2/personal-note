## 개요
프로그램 실행 시점에 변수, 함수 등 **모든 구성 요소의 데이터 타입이 할당에 의해 결정**되는 언어. 대표적으로 JavaScript, Python, PHP, Ruby, Lisp, Perl 등이 있다.

코드 작성 시 타입을 명시할 필요가 없어 개발 속도가 빠르고 유연성이 높지만, 실행 전에는 타입 에러를 감지하기 어렵다는 특징이 있다.
## 장점
- **높은 유연성 및 생산성:** 타입을 명시하거나 복잡한 타입 제한을 따르지 않아도 되므로, 아이디어를 빠르게 코드로 구현할 수 있고 프로토타이핑에 유리하다.
- **낮은 진입 장벽:** 데이터 타입에 대한 깊은 이해 없이도 쉽게 코드를 작성할 수 있어 초보자가 배우기 비교적 수월하다.
- **코드 간결성:** 타입 선언을 생략할 수 있어 소스코드가 전반적으로 깔끔하고 간결해진다.
- **메타프로그래밍 용이성:** 런타임에 객체의 구조나 타입을 동적으로 변경할 수 있어, 유연하고 강력한 프레임워크나 라이브러리를 구축하기 쉽다.
## 단점
- **신뢰성 저하 (런타임 에러 가능성):** 컴파일러의 타입 검사가 없기 때문에, 사소한 타입 오타나 잘못된 타입 전달로 인한 오류가 실제 프로그램 실행 중에 발생할 수 있다.
- **유지 보수성 저하:** 복잡한 프로그램에서는 변화하는 변수 값을 추적하기 어려울 수 있다. 변수 타입이 항상 바뀔 수 있기 때문에 값을 확인하기 전에는 타입을 확신할 수 없다.
- **성능 저하:** 실행 시점(런타임)에 변수의 타입을 계속 확인하고 해석하는 과정이 필요하므로, 정적 타입 언어에 비해 실행 속도가 상대적으로 느리다.
- **도구 지원의 한계:** IDE가 코드를 분석할 때 타입을 명확히 알 수 없어, 자동 완성이나 리팩터링 기능의 정확도가 정적 타입 언어보다 떨어질 수 있다.
