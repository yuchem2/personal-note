## 질문 리뷰
- 15.1.3에서는 GlobalScope의 위험성을 언급하고 있다. 위험에도 불구하고 사용해야만할 상황이 있으니 존재한다고 생각하는데, 어떨 때 사용되는가? 책에서는 예시로 애플리케이션의 전체 생명주기 동안 활성 상태를 유지해야하는 최상위 백그라운드 프로세스를 예시로 들었는데, 다른 예시가 있을까?
    - 이름부터 전역적으로 구성. 앱에서 전역으로 돌아가는 요소가 있어야만 사용할 것.
    - 안드로이드나 서버 등은 사용자의 입력이 들어왔을 때만 사용하기 때문에 이런상황에서는 필요없음
    - 메인스레드의 동작 여부와 다르게 동작해야하며, 그 작업이 메인 스레드가 죽기 전에 끝나야하는 작업이 있는 경우 사용하기도 함
    - iOS 갤러리 앱을 보면 지도 상에 사진을 어디서 찍었는지 알 수 있는 기능이 있음. 이러한 기능을 안드로이드 버전의 앱을 만드는 작업을 한 경험이 있는데, 이런 작업을 할려면 핸드폰에 있는 모든 사진을 분석해서, 좌표 메타데이터를 찾고, 정규화하고, 메모리에 올리고, 화면에 뿌려줄 수 있어야 함. 근데, 사진이 보통 적게는 100장에서 몇백만장 등 편차가 매우 큼. 이런 작업을 스레드를 100개를 열어서 하면 컨텍스트 스위칭으로 인해 부하가 엄청난데, 이런 작업을 병렬적으로 돌리면서 메인 스레드를 막히지 않는 작업에서 사용해본 경험이 있음. (이런 작업이 항상 메인 스레드의 중단보다 종료가 빠를 것이라고 예측했음)
- IO 작업은 임시 중단 시점인가?
    - 기본적으로는 블로킹 함수임. 
    - 하지만 블로킹 함수를 async와 같이 래핑해놓은 라이브러리 등을 사용하면 그러면 임시 중단 함수가 됨
    - 그래서 일반적인 java api IO 작업을 수행하면 블록킹으로 인해 성능이 낮아질 수 있음
- Android가 코틀린을 많이 사용하는가?
    - 일반 서버보다 더 많이 신경써야하고, 많이 사용된다. 이후 배울 플로우과 같은 기능이 Android에서 많이 사용됨.
