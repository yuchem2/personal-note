- 어노테이션 = 타입스크립트의 데코레이터에서 많이 사용했고, 구현도 해봤어서 쉽게 읽었다. 코틀린에서는 어노테이션을 이렇게 다루는구나. 리플렉션을 통해 런타임에 정보를 얻는 점도 유사해서 쉽게 읽었던 것 같다.
- DSL = DSL이라는 키워드에 숨겨진 수신 객체 람다를 받는 함수를 구현하고, 활용할 수 있는 방법을 보여주는 챕터라고 느낌. 이걸 잘 사용하면 보다 코드를 쉽고 간단하게 작성할 수 있다고 생각이 들었음. 리액트 네이티브를 쓸 때 gradle 문법을 코틀린으로 써야했는데, 이 챕터를 읽으면서 해당 부분이 이런식으로 구현되었겠구나를 느낌
- DSL 예시를 보다 보니 이전에 한빈님이 짚어주셨지만, 중위 호출을 적절히 사용한다면 코드를 더 읽기 쉽게 짤 수 있다는 것을 느꼈음.
## 질문 리뷰
- invoke 관례가 JVM에서 함수타입을 FunctionN 인터페이스로 구현하면서 자연스럽게 연결된 것으로 이해했는데, 실제 작업에서 invoke 관례를 람다 외의 객체에 적용하는 경우가 있나요?
    - 있지만 드물다. 가끔 있지만, 개인적으로 직접 해본적은 없다. 하지만 구현되어 있는걸 가져다가 쓴 경우가 있음
- 코틀린 DSL 관련해서 실제로 많이 사용되는 것인지? 사용하고 있다면 기존 명령형 코드에 비해 어떤 비중을 두고 사용하는것인지? 어느 기능에서 많이 사용하는 것인지?
    - 스터디장님은 코루틴 다음으로 좋아하는 기능
    - 코틀린도 DSL 관련된 라이브러리가 매우 많음. ex) 익스포즈드
    - 익스포즈드를 보면 DSL를 어떻게 쓰면 좋은지 알 수 있음
    - selenium과 같은 코틀린 버전도 있는데, DSL로 작성되어 있음
    - 어떨 때
        - 구조화된 데이터를 만들거나, 파싱할 때
        - DDD가 깊어지면 특정 도메인이 가져야하는 메서드, 역할 등이 생기게 되는데, 그러면 그 데이터는 구조화되었다고 할 수 있음. 그래서 DSL은 DDD와 궁합이 좋음
- 코프링을 쓸 때 JPA를 쓸 때 쿼리 DSL을 쓰시나요? 아니면 다른 코틀린스러운 DSL?
    - 쿼리 DSL와 같은 코틀린 JDSL(네이버 라인)이 있음. 쿼리 DSL을 쓰기 싫은 사람들이 씀. 특히 스프링과 궁합이 좋음
    - JDSL 2.x 버전이 개인적으로 코틀린 스럽다고 생각함. 하지만 오래된 버전이라 최신 버전을 쓰고 싶다면 3.x 버전을 추천
