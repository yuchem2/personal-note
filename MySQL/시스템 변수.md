MySQL 서버는 기동하면서 설정 파일의 내용을 읽어 메모리나 작동 방식을 초기화하고, 접속된 사용자를 제어하기 위해 이 값들을 별도로 저장한다. 이 저장된 값을 시스템 변수라고 한다.

```mysql
/* 아래 명령어를 통해 시스템 변수를 조회할 수 있다. */
SHOW GLOBAL VARIABLES;
SHOW VARIABLES;
```

각 시스템 변수는 5가지 속성으로 구분할 수 있다.
- Cmd-Line: MySQL 서버의 명령행 인자로 설정될 수 있는 여부
- Option file: MySQL 서버의 설정 파일인 `my.cnf`로 제정할 수 있는지 여부
- System Var: 시스템 변수인지 여부
- Var Scope: 시스템 변수의 적용 범위를 나타낸다. Global, Session, Both로 구분한다.
- Dynamic: 시스템 변수가 동적인지 여부 

시스템 변수의 적용 범위에 따라 시스템 변수를 Global, Session, Both로 구분할 수 있다.
- Global: 하나의 MySQL 서버 인스턴스에서 전체적으로 영향을 미치는 시스템 변수
    - 주로 서버 자체에 관련된 설정인 경우가 많다.
    - ex) InnoDB 버퍼 풀 크기(innodb_buffer_pool_size), MyISAM의 키 캐시 크기(key_buffer_size) 
- Session: 클라이언트가 MySQL 서버에 접속할 때 기본으로 부여하는 옵션의 기본값을 제어하는데 사용.
    - 여기서 기본 값은 Global 변수이지만, 각 클라이언트가 가지는 값이 Session 변수이다.
    - 각 커넥션의 Session 변수는 서버에서 강제로 변경할 수 없다.
- Both: Session 범위의 시스템 변수 가운데 [설정 파일](설정%20파일.md)에 명시해 초기화할  수 있는 변수
    - 커넥션이 생성되는 순간에 해당 커넥션의 기본값으로 사용되는 변수

서버가 가동 중인 상태에서 변경 가능한지 여부로 동적/정적 변수를 구분할 수 있다. 

```mysql
# 변수 검색
> SHOW GLOBAL VARIABLES LIKE '%max_connections%';
# 변수 수정 (동적인 경우 즉시 반영된다)
> SET GLOBAL max_connections=500;
# SET PERSIST을 이용하면 자동으로 설정 파일에도 기록한다.
> SET PERSIST max_connections=500;
# GLOBAL 변수를 빼면 자동으로 세션 변수가 변경된다.
> SET sort_buffer_size=4194304;
```

> `SET PERSIST` 명령어를 사용하면 `mysqld_auto.cnf`라는 JSON 형식의 파일에 변경사항이 기록되고, [설정 파일](설정%20파일.md)을 읽은 뒤 `mysqld_auto.cnf`에 있는 값으로 덮어쓴다. 그러나 해당 명령어는 세션 변수에는 적용되지 않는다. `SET PERSIST_ONLY`을 사용하면 실행 중인 서버에는 적용되지 않는다. 변경사항을 없애고 싶으면 `RESET PERSIST`로 삭제할 수 있다.
> 
> 이렇게 변경된 시스템 변수의 메타데이터는 `performance_schema.variables_info` 뷰와 `performance_schema.persisted_variables` 테이블을 통해 참조할 수 있다.

정적 변수는 디스크에 저장된 설정 파일의 내용을 변경하더라도 서버를 재시작하기 전에는 변경사항이 적용되지 않는다. 동적 변수라면 `SET` 명령으로도 서버 재시작 없이 간단히 변경할 수 있다. 만약 범위가 `Both`라면, Global 변수를 수정하더라도 이미 존재하는 커넥션의 Session 변수 값은 변경되지 않고 유지된다.
