데이터베이스 서버에서 테이블의 구조 정보와 스토어드 프로그램 등의 정보를 데이터 딕셔너리 또는 메터데이터라고 한다. 

MySQL 5.7까지는 테이블의 구조를 FRM 파일에 저장하고, 일부 스토어드 프로그램 또한 파일(`*.TRN`, `*.TRG`, `*.PAR`, ...) 기반으로 관리했다. *이로 인해 생성 및 변경 작업이 트랜잭션을 지원하지 않았고, 비정상적인 종료로 일관되지 않은 상태로 남는 경우가 생겼다.* 

MySQL 8.0부터는 이러한 문제를 해결하기 위해 테이블의 구조 정보나 스토어드 프로그램의 코드 관련 정보를 모두 [InnoDB 스토리지 엔진](InnoDB%20스토리지%20엔진.md)을 사용하도록 개선하였다. 시스템 테이블과 데이터 딕셔너리 정보를 모두 모아서 [mysql DB](mysql%20DB.md)에 저장한다. *트랜잭션 기반 동작으로 변경되면서 비정상 종료라도 스키마 변경이 완전한 성공/실패로 수행된다.*

[InnoDB 스토리지 엔진](InnoDB%20스토리지%20엔진.md) 테이블은 위의 설명과 같이 테이블 기반의 딕셔너리에 저장되지만, [MyISAM 스토리지 엔진](MyISAM%20스토리지%20엔진.md)이나 CSV 등과 같은 스토리지 엔진의 메타 정보는 SDI(Serialized Dictionary Infromation) 파일에 저장된다. 이 파일은 기존의 FRM 파일과 동일한 역할을 한다. 

> [InnoDB 스토리지 엔진](InnoDB%20스토리지%20엔진.md) 테이블의 구조도 SDI 파일로 변환할 수 있다. ibd2sdi 유틸리티를 이용하면 InnoDB 테이블 스페이스에서 스키마 정보를 추출할 수 있다.
