MySQL 8.0부터는 [사용자 권한](사용자%20권한.md)을 묶어서 역할로 사용할 수 있게 됐다. 실제 MySQL 서버 내부적으로는 역할은 계정과 똑같은 모습을 하고 있다. **역할은 직무를 분리할 수 있게 해서 보안을 강화하는 용도로 사용할 수 있기 위함이다.**

```mysql
# 역할 정의
CREATE ROLE role_emp_read, role_emp_write;
# 권한 부여
GRANT SELECT ON employees.* TO role_emp_read;
GRANT INSERT,UPDATE,DELETE ON employees.* TO role_emp_write;
# 역할 부여
GRANT role_emp_read TO 'reader'@'127.0.0.1';
GRANT role_emp_read,role_emp_write TO 'writer'@'127.0.0.1';
# 역할 부여만으로 실제로 역할이 수행되는 것이 아니라 활성화해야 한다.
# 활성화하면 역할이 가진 권한을 수행할 수 있지만, 재접속하면 역할이 활성화되지 않은 상태로 초기화된다.
SET ROLE 'role_emp_read';
# 자동활성화 여부를 시스템 변수로 설정 가능
SET GLOBAL activate_all_roles_on_login=ON;
```

역할은 사용자 계정과 동일하게 취급되어 mysql DB의 user 테이블에서 권한과 유저 관계 없이 저장된 것을 확인할 수 있다. 단지 하나의 사용자 계정에 다른 사용자 계정이 가진 권한을 병합해 권한 제어가 가능해졌을 뿐이다.
```mysql
------------------------------------------------
| user           | host       | account_locked |
| role_emp_read  | %          | Y              |
| role_emp_write | %          | Y              |
| reader         | 127.0.0.1  | N              |
| writer         | 127.0.0.1  | N              |
| root           | localhost  | N              |
------------------------------------------------
```

MySQL 서버는 권한과 계정을 구분하지 않고, 단순히 하나의 계정에 다른 계정의 권한을 병합하여 역할에 포함된 권한을 계정에 부여한다. 역할에 입력된 호스트는 아무런 영향이 없다. 나중에 해당 역할로 로그인을 하게 된다면 그때는 중요해진다.

계정의 기본 역할 또는 역할에 부여된 역할 그래프 관계는 `SHOW GRANTS` 명령을 사용할 수도 있지만 mysql DB의 권한 테이블을 참조하면 깔끔하게 볼 수 있다.
- `mysql.default_roles`: 계정별 기본 역할
- `mysql.role_edges`: 역할에 부여된 역할 관계 그래프
